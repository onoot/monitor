# corpus.md — реестр паттернов A/D-уязвимостей

Реестр собран из трёх источников и используется как обоснование для
`ad/rules.py` и `ad/semantics.py`. Каждая запись: где найдено, какой detector
закрывает, и почему это ломает чекер или защиту флага.

**Правило:** запись попадает сюда только если подтверждена чтением исходников.
Догадки и «похожие на» сюда не пишутся.

Источники:

- `services/` — 4 локальных сервиса (writeup + исходники, проверено)

### Устойчивые анти-паттерны (обязательно НЕ срабатывать)

Эти места — ложные positives, на которых ломался анализатор. Закреплены тестами.

| Место | Что там | Почему это безопасно |
|---|---|---|
| `magicapp/sql.py:36,46,57,63` | `cursor.execute("... WHERE id = %s", (userid,))` | Параметры связаны через кортеж. Плейсхолдер + биндинг ≠ инъекция |
| `backend/src/users/users.service.ts:225` | `createHash("sha256").update(body.password)` | `.update(` — это метод, а не `UPDATE` в SQL |
| `magicapp/routes.py:47` | регистрация читает пароль из формы | Легитимное использование: пароль сохраняется. Слабость — хранение (`AD-CRYPTO-004`), а не проверка |
| `backend/Public/js/index.js:78` | `/users/:id` без guard на регистрации | Handler сам проверяет `Authorization`; detector обязан это разрешить |

Detector-специфика, а не уязвимость:

- `AD-AUTH-002` идёт от регистрации маршрута, ищет определение handler'а по имени
  функции и по имени модуля, и **понижает confidence до `low`**, если handler не
  удалось однозначно найти. Молча подавить находку он не может — неоднозначность
  обязана быть видна в отчёте.
- Одна соседняя `@UseGuards` не должна закрывать соседний роут: блок роута
  ограничен следующим объявлением маршрута.

| 16 | InGalaxy | Токен диалога выводится детерминированно: `md5(md5(login1).md5(login2))` | Утечка через предсказуемость: чужой токен воспроизводим |
| 17 | InGalaxy | Имя загружаемого файла = `md5(...)` от содержимого/имени, путь выводится из пользовательского ввода | Обход проверки расширения через переименование |
| 18 | InGalaxy | Дамп `/users` отдаёт всё поле `users` без фильтрации | Массовый дамп = источник чужих флагов (см. п. 9) |

Обобщения для движка:

- **Детерминированные производные секреты** (п. 16) ловятся эвристикой «secret =
  hash(known_public_values)». `AD-CRYPTO-003` — частный случай (AltayCoin).
- **IDOR по полю тела** (п. 15) — отдельный класс: авторизация берётся из входа, а
  не из сессии. В текущем пакете покрыт слабо, кандидат на `AD-PRIV-005`.
- **Массовый дамп** (п. 18) — источник флагов для соседних команд; именно его
  отравление опасно, потому что меняет чужое очко.

## 3. AltayCTF 2018 — механика чекеров

Это не уязвимости сервисов, а **контракт чекера**. Нужен, чтобы восстановить
жизненный цикл без доступа к исходникам чекеров (`ad/topology.py`).

| # | Наблюдение | Зачем движку |
|---|---|---|
| 19 | `IP_PATTERN` — шаблон IP вида `{TEAM}-{ROLE}` | Позволяет восстановить IP инстансов команд из исходников. Checker IP отсюда **не** извлекается |
| 20 | `rstr.xeger` для генерации значений | Формат флага приходит xeger-шаблоном → нужен разбор подмножества xeger |
| 21 | Учётные данные чекера хранятся в MongoDB и переиспользуются между раундами | Жизненный цикл с состоянием между раундами, а не stateless-проверка |
| 22 | Фазы: index → register → save/auth → operations → put → get_old | Порядок фаз, который нужно выводить из трафика |
| 23 | Чтение значения, положенного **в этом же раунде** (same-round) | Отличает «флаг только что положен» от «флаг положен раундом ранее» |
| 24 | Чтение значения, положенного **в прошлом раунде** (`get_old`) | Флаг обязан переживать раунд; отравление обязано сохранять и это |
| 25 | Идентификаторы извлекаются из ответа регуляркой по ID | Восстановление «это запрос чекерной фазы put/get» без знания исходников |

Следствия, уже реализованные:

- `ad/flags.py::xeger_to_regex` разбирает `[a-z0-9_]{16}`, `[a-z]{4}` и литералы;
  шаблоны с встроенным regex **отклоняются** (иначе получился бы regex, который
  матчит не то). Регрессия: `tests/test_ad.py::Flags`.
- `ad/topology.py::lifecycle()` перечисляет фазы 19–25 как ожидаемые, а не
  наблюдаемые; отчёт обязан помечать «не подтверждено», пока нет трафика.
- Стадия old-round (п. 24) — причина, почему отравление детерминировано и
  сохраняет длину: значение, прочитанное чекером в следующем раунде, обязано
  пройти его же валидацию.
